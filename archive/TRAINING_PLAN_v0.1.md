# 自有中文对话安审模型训练与评测计划 v0.1

编制日期：2026-09-22。状态：方案与验收设计，尚未下载训练数据、运行基线或启动训练。下文规模、超参数和门槛均为拟定实验目标，不是已有结果。

**1. 目标与首版选择**

训练一个独立于业务 LLM 的中文审查模型：先判断用户请求，再结合对话历史判断助手回答；统一支持一次性文本和增量文本，返回结构化概率、风险类别、证据位置及建议动作。首版面向文本，不处理图像、音频或视频。

主线采用 Qwen3Guard-Stream-0.6B 继续训练，保留因果 Transformer 与非生成式分类；4B 作为质量对照及可选复核器。另设 Qwen3-0.6B 通用主干加分类头的对照，以验证收益是否来自现成安审训练。优先解决数据与评测，不从零预训练，也不以 RLCD 为第一阶段目标。官方 Jev 的完整实现未公开，NanoJev 不作为本项目主要训练框架。[1]

交付包括：政策标签规范、数据来源清单、独立评测集、可重复基线、训练权重、增量推理服务、模型卡及上线前影子评测报告。模型称为“自有安审模型”，不宣称通过某项监管备案或覆盖未公开的官方词库。

**2. 标签体系：识别什么，与如何处置分开**

| 层次 | 标签或字段 | 定义 |
|---|---|---|
| 内容类别 | 多标签 topic/risk_category | 同一段内容可以同时涉及政治公共事务、隐私、暴力、诈骗等；涉及话题不等同于违规 |
| 政策判断 | policy_id、policy_version、violation_label | 按有版本的具体规则判断；需要明确适用范围、允许情形、禁止行为和正反例 |
| 信息状态 | sufficient / insufficient / disputed | 区分前缀尚不完整、政策存在争议和明确判断；不把所有模糊样本归为违规 |
| 危害程度 | severity | 仅对定义明确、确有标签的风险训练；缺失标签不自动填零 |
| 证据 | evidence_spans、decidable_at | 风险相关文本范围，以及首次有足够可见信息作出判断的位置；两者可能不同 |
| 服务动作 | allow / hold / review / block | 由策略层基于类别、概率、证据、版本和场景作出 |

用户请求和助手回答分别标注。危险请求下的安全拒答，应是“输入有风险、回答无对应违规”；用户正常提问下助手自行生成的违规回答也必须覆盖。

中国政治与公共事务相关内容设置独立专题测试，但不以政治立场、人物名称、政府批评本身替代具体违规判据。必须覆盖新闻、历史、学术、引用、反驳、讽刺、一般批评及具体有害行为的区别。内容分类与政策标签分别保存；政策无法裁定的样本进入仲裁或 review，不伪造一致答案。

政策表建议字段：rule_id、版本、生效日期、风险定义、允许例外、适用角色、证据要求、训练正反例、处置等级、依据来源。研究人员与政策负责人共同完成约 300–500 个种子例，双人独立标注后仲裁。先解决标注不一致，再扩大数据。

当前没有核验到网信办官方完整关键词库的公开下载。社区词库仅用于召回线索和构造边界样本，不能直接作为监督真值。现行 GB/T 45654-2025 可作为政策覆盖核对入口；具体条文应取得现行全文再映射，不把 2024 年技术文件直接当作现行标准全文。[11][12]

**3. 模型与推理设计**

```text
服务端固定角色边界 + 对话历史 + 当前新增文本
                    ↓
       因果 Transformer（保存自身 KV Cache）
                    ↓
       输入头 / 输出头（按当前角色读取）
                    ↓
  多标签类别 + 违规概率 + 信息状态 + 可选证据定位
                    ↓
         概率校准 + 版本化策略层
                    ↓
       放行 / 暂存 / 复核 / 拦截
```

使用固定维度分类头，不生成解释文字或思维链。对于新标签，可保留原始风险头并新增类别、信息状态和定位头，避免训练开始时丢掉所有已有能力。原生类别与自有类别保存显式映射，不能靠名字近似直接合并。

完整输入使用一次因果前向，在目标消息结束位置读总体分类，并按需要检查中间位置。流式模式首次 prefill 历史，随后仅处理新 token。每个新增 token 都可有风险输出；即使按块调度，也不能只看块末尾而漏掉块内瞬时风险。采用经验证的片段聚合策略，最终分类与“曾有风险的历史事件”分别记录，避免长对话中一次疑似命中永久污染所有后续消息。

用户 role、assistant role、工具来源等边界由服务端构造；待审内容中的伪造角色字符串不得改变真实消息身份。生产分类输入不包含训练标签、人工说明或未来文本。先以固定政策 profile 训练；不同政策可调阈值和动作，语义定义发生变化则需重新标注/训练，不宣称任意新规则都能零样本支持。

缓存和分词要求：

- 审查模型使用自己的缓存，与被审查 LLM 不共享权重相关 KV。
- 同一模型与 tokenizer 下，相同历史 token、角色模板、位置编码、适配器版本可复用前缀；策略若作为输入影响主干，也纳入缓存键。纯后处理阈值变化不需重算隐藏状态。
- tokenizer 不同则接收文本增量；保留未稳定分词的尾部，发生 token 修订时回滚到最后一致前缀。不得把各文本块分别编码后盲目拼接。
- 缓存按会话隔离，设置 TTL 和内存上限；历史编辑、分支重试、模型更新、长上下文裁剪均定义明确的重建策略。上下文不能静默截断；超长进入单独评测路径。
- 模型输入、词库规范化视图和用户原文分别保留位置映射，防止繁简转换、零宽字符清理后证据偏移。
- 公开 Qwen3Guard 包装实现需要专项验证：本次看到的 stream_generate 每步传入增长的完整序列。自行实现或修复真正增量路径，不能仅凭接口名称认定缓存有效。[2]

流式服务将 LLM 输出先写入暂存区，经审核再释放。初始比较 1/8/16/32 token 的调度块，以及按句缓冲；实际取舍由延迟、泄漏量和误拦决定。提供 released_until 原文字符位置、审查 seq_id、角色、is_final、策略版本，防止重复或乱序事件错误放行。hold 表示等待更多语义，review 表示需要其他判断来源；超时、断线、审查器失败不能默认为放行。

已展示文本不可追回，后文也可能改变前文含义。严格场景按句或整段缓冲；不承诺流式的零延迟与零泄漏同时成立。

**4. 训练数据来源及使用方式**

| 来源 | 已公开内容 | 在本项目的用途 | 必须处理的问题 |
|---|---|---|---|
| ShieldLM [3] | 2,000 中文 + 2,000 英文训练样本，含安全判断；完整训练集未全部公开 | 小规模训练和数据适配的起点 | 提取判断标签与自定义规则，解释不直接作为线上输入；审计数据来源与许可 |
| SafeConv [4] | 约 16 万 prompt-response 对，输入/输出安全标签、风险 span、安全改写 | 双向分类与片段定位候选来源 | 使用训练划分；核实实际语言、文件和许可；span 起点不自动等于可判定时点 |
| CValues-Comparison [5] | 约 14.5 万中文偏好对，约 11.6 万训练、2.9 万测试 | 中文覆盖、同题不同回答的对比 | 不把所有负例标成 unsafe；有些是安全答案之间的质量偏好；补绝对标签 |
| Safety-Prompts [6] | 中文问题、回答、场景类型、指令攻击 | 输入风险与越狱来源候选 | 场景标签不直接等于违规；回答独立标注；官方未公开敏感话题场景数据 |
| BeaverTails [7] | 英文问答与 14 类人工风险标签，有训练划分 | 通用风险与英文回归；研究分支可选 | CC BY-NC 4.0；不同划分/版本可能重叠，去重；不直接给输入套用回答标签 |
| PKU-SafeRLHF [8] | 英文回答安全性、19 类风险、严重程度、偏好 | 严重程度及多标签研究对照 | CC BY-NC 4.0；使用绝对风险标签，区分 helpfulness 与 harmlessness；与其他 PKU 数据去重 |
| 自有授权数据 | 尚待建设 | 中文目标政策、多轮、正常业务、流式边界的主要增量 | 来源授权、去标识、双人标注；不得默认为可读取任何现有私有对话 |

数据许可按“可用于目标训练 / 仅非商业研究 / 待确认 / 不可用”登记。待确认数据隔离，不进入任何训练运行。公开代码许可不能替代数据许可。非商业数据若用于研究，权重、数据和运行记录单独登记；后续商业模型需从合适的基座重新用获准数据训练，不能通过删掉原始文件洗掉已训练权重的来源。

模型的已有训练数据也可能不完全透明；记录上游模型许可和已知来源，而不宣称有完整数据血缘。就本次调查而言，Qwen3Guard 的完整 119 万训练样本没有找到公开下载入口；公开的 Qwen3GuardTest 是测试集。[1][9]

**5. 自建数据规模与配方**

先做 2,000 条质量校验样本，再逐级扩展到 20k / 50k / 100k 独立对话记录，画数据规模学习曲线。100k 是上限实验目标，不要求在数据质量未验证时一次做满。

建议 100k 训练配方如下；各行互斥按主任务计数，但一条记录可监督多个头。公开数据合格训练样本与自有样本共同填充，不机械追求某个来源比例。

| 主任务 | 拟定独立记录数 | 要解决的问题 |
|---|---:|---|
| 一般中文输入/输出分类 | 40,000 | 建立通用安审能力，涵盖安全和违规文本 |
| 目标政策与困难正常样本 | 20,000 | 区分主题、表达方式和具体政策边界；含政治公共事务正常讨论 |
| 多轮与指令注入/绕过 | 15,000 | 指代、上下文累积、角色伪造、词汇变体 |
| 流式与位置监督 | 15,000 | 部分前缀、完整句、首次可判定点、跨块命中 |
| 英文/中英混合与回归 | 10,000 | 防止中文适配破坏原有跨语言能力 |
| 合计 | 100,000 | 不含 dev、calibration、test，也不把多次截断计成独立对话 |

若授权数据不足则缩小对应规模，以实测学习曲线决定是否扩充，不拿测试数据补足。目标总体约一半安全、一半有风险/争议，具体按角色和类别检查；另保留真实业务发生率的影子集，避免用平衡训练集推算线上准确率。每个拟上线关键类别初期至少争取 500 个违规训练样本和 500 个相近安全反例；不足时合并标签或转人工，不能宣称覆盖完成。

四种输入/输出组合均需出现：安全问/安全答、危险问/安全拒答、危险问/危险答、安全问/危险答。正常长回答、引用后反驳、拒绝开头后泄漏、正常开头后转风险也作为独立测试维度。

标注流程：先人工确定指南和金标种子；可用获准模型辅助生成候选与预标注，但同源教师预测不是测试真值。目标政策、争议和风险边界样本双人标注及仲裁；其余分层抽检。不同标注人分别看到当前前缀与完整上下文，避免把未来信息泄漏给前缀判断。记录原始分歧，不强行把无法判定的例子标成安全。

**6. 数据格式与隔离**

统一 JSONL 至少包括：

```json
{
  "id": "example-0001",
  "source": "owned-or-approved-source",
  "source_revision": "pinned-revision",
  "license_status": "approved-for-target-use",
  "origin_group_id": "shared-origin-id",
  "language": "zh",
  "messages": [{"role": "user", "content": "示例问题"}],
  "target_message_index": 0,
  "target_role": "user",
  "policy_version": "policy-v1",
  "labels": {
    "violation": false,
    "categories": [],
    "information_state": "sufficient",
    "severity": null
  },
  "label_mask": {"violation": true, "severity": false},
  "evidence_spans": [],
  "prefix_annotations": [],
  "split": "train",
  "annotation_origin": "human-adjudicated"
}
```

位置统一用原文 Unicode 字符偏移，训练/评测时按固定 tokenizer 生成 token 映射；直接使用 Qwen3GuardTest 的 token 位置时必须遵循它的 tokenizer/模板，跨模型时先映射回文本。缺失标签用 mask 跳过损失，不能当负例。

除训练集外，拟另外建设 dev 5k、calibration 5k、冻结业务 test 8k，均按原始问题/对话/文档/模板来源分组后再划分；所有改写、翻译、前缀和成对回答跟随原始记录。先做精确及近似去重，再跨数据源排查，避免 ShieldLM 与 CValues/BeaverTails 等来源重叠。

dev 用于结构和 checkpoint 选择；calibration 用于概率与动作阈值；test 只用于阶段验收。测试集中发现的错误可归纳成类别后在新 train 来源上补数据，但不得直接训练这些测试记录、它们的改写或答案；反复用于设计决策的测试集退役为开发集并另建新 test。

公开 benchmark 可能已被上游模型见过，不能证明训练前完全未污染。因此自建时间较新的冻结集和跨来源 OOD 集是主要上线证据，公开榜单只提供参考。

**7. 基线模型与公平比较**

| 编号 | 基线 | 回答的问题 |
|---|---|---|
| B0 | 词库/规则，阈值和规则冻结 | 最低成本系统能做到什么，误拦在哪里 |
| B1 | 原版 Qwen3Guard-Stream-0.6B | 默认小模型的类别、误拦、流式能力 |
| B2 | 原版 Qwen3Guard-Stream-4B | 更大模型是否值得增加推理成本；不假定它一定更好 |
| B3 | Qwen3Guard-Gen-4B | 完整消息生成式审查的质量/延迟对照，必要时疑难复核 |
| B4 | Qwen3-0.6B 通用主干 + 相同自有分类头 | 验证现成 Guard 初始化的收益；与主线使用相同数据和更新预算 |
| T1–T4 | 下文逐级训练版本 | 衡量每类数据和训练目标的增益 |

先运行 B0/B1/B2；B3/B4 在实验框架稳定后加入。分两条报告：原生 benchmark 协议保持原始标签；业务评测使用预先固定的类别映射，controversial 不静默折成 unsafe，无法映射的标签注明 unsupported/review。

每个模型可在同一 calibration 集上调到相同误拦率或复核预算后比较召回，不能让某个模型通过全部 review 取得虚高安全率。B0 无连续概率时，报告它实际可达的 operating point，不伪造可调曲线。生成式基线如只有离散标签，不把文字自报置信度当校准概率。

输入文本、历史长度、角色模板语义、政策版本、采样集和硬件条件一致。类别无对应输出时，不用测试标签帮助映射。保存所有原始预测而不仅是最终平均数。

**8. Bench 组合：分类、流式和系统三层分别看**

| Bench | 使用范围 | 测量内容 | 接入方法与限制 |
|---|---|---|---|
| 自建业务 Guard-Test-v1（拟 8k） | 核心冻结测试 | 输入/输出分类、目标政策、误拦与校准 | 拟 3k 正常、3k 违规、2k 多轮/模糊/边界；分别报告，不伪装成真实业务比例 |
| 自建 Stream-Gold（拟 2k，含在上述 8k 中） | 核心流式测试 | 首次可判定点、延迟、已释放风险量、切块稳定性 | 约 1k 风险、1k 正常；不是在公开位置测试集上补训练 |
| Qwen3GuardTest [9] | 原生公开流式回归 | 完整判定、首个风险句位置、原生命中指标 | thinking / thinking_loc / response_loc 分开；后两者是风险样本，不能单独测误拦；不是三个互不重叠的大训练分片 |
| SafeConv 官方 test [4] | 同分布位置与对话回归 | 输入/输出标签、span 定位 | 如果训练使用其 train，这只是 ID 测试，不当作跨域泛化证明；许可先核实 |
| CValues 官方 test [5] | 中文成对回答对照 | 安全排序和经补标的绝对风险 | 原始偏好不等于二分类真值；保留作者划分且剔除跨来源泄漏 |
| BeaverTails / PKU 官方 test [7][8] | 英文风险回归 | 分类、类别、严重程度 | 研究/许可边界保留；数据来源重叠时不要简单合计成独立样本 |
| CHiSafetyBench [10] | 中文类别覆盖与系统评测 | 5 大领域、31 类的识别/防护覆盖 | QA 作为风险请求场景；固定 LLM 生成/回放回答，另标回答真值测 Guard；MCQ 是安全知识/选择能力，不能直接当二分类分数 |
| SafeDialBench 中文部分 [13] | 多轮系统评测 | 跨轮绕过与防护一致性 | 保留其会话结构，固定业务 LLM；补逐轮输入/回答金标，报告为 adapted protocol |
| FLAMES 公开 1k [14] | 中文对抗系统评测 | 复杂提示下回答有害率和正常任务保留 | 公开的是提问；需要固定生成器的回答和独立标注，不可把原榜单分数当 Guard 分类 F1 |
| SafetyBench [15] | 可选离线辅助 | 安全知识，多选题 | 不作为首版核心门槛；固定分类头不天然支持通用选项作答，不为刷分另造答案映射 |

系统对照固定生成模型、版本、采样参数、问题和 seed，比较“无 Guard / 原版 Guard / 自训 Guard / 自训 Guard + 复核”。第一轮用离线回放隔离生成随机性；第二轮测真实取消、重试、缓冲释放和最终用户可见文本。正常任务完成率与违规泄漏率一起看，禁止用“全部拦截”作为有效改进。

适配后的 benchmark 名称必须带 adapted，不与原始排行榜直接比较；自动裁判独立于训练教师和被测 Guard，关键样本人工复核。测试许可与训练许可同样登记，NC 测试集不能默认用于商业评估活动。

**9. 观测指标与候选门槛**

以下是 v0.1 拟议目标，用于形成明确实验方向。基线测量后可在查看最终测试成绩之前修订并冻结。达不到时报告失败或能力边界，不能为了通过而事后改测试阈值。

| 维度 | 指标 | 候选验收目标 |
|---|---|---|
| 静态风险识别 | Recall@FPR≤1%，类别 Macro-F1、PR-AUC | 相比 B1 同等 FPR 下，目标业务漏检相对下降 ≥20%；必须同时报告绝对百分点变化与置信区间 |
| 一般正常内容 | 最终误拦率、hold/review 率 | 冻结正常集误拦率点估计 ≤1%；复核不能隐藏在 allow 中 |
| 困难正常内容 | 新闻/历史/引用/批评等分组 FPR | 单独报告，并拟不超过 B1；关键分组拟控制在 2% 内，样本不足则不给达标结论 |
| 关键风险类别 | 每类漏检率与样本数 | 初期目标召回 ≥95%，约 200 条独立测试例/关键类别作为起点；不等于统计上已证明真实召回达到 95% |
| 多轮 | 每会话漏检率、误拦率 | 对比单轮与完整历史，跨轮攻击不能只报逐消息平均 |
| 流式检测 | 可判定点后的 detection lag、漏检率 | 对已检测样本报告 P50/P95；同时报告未检测比例；先评估 ≥95% 在可判定后 32 token 内检测的可达性 |
| 流式误拦 | 正常完整消息任一错误拦截概率 | 作为主要在线误拦指标；不能用很低的逐 token FPR 掩盖累计错误 |
| 实际泄漏 | 放行到用户的风险字符/token 数、零泄漏比例 | 同一缓冲预算下不劣于 B1，量化延迟与泄漏的 Pareto 曲线 |
| 校准与复核 | Brier、NLL、可靠性图、ECE、risk-coverage | 业务 calibration 拟合后在 test 报告；同等 ≤5% 复核预算比较自动判定错误率；ECE 不单独决定好坏 |
| 原有能力回归 | 英文及通用风险集 F1/Recall | 与 B1 相比拟下降不超过 2 个百分点；按具体类别检查 |
| 增量正确性 | 同一 token 前缀的整段/缓存概率差、chunk 不变性 | 固定推理精度下先设概率绝对差 ≤1e-3 的工程目标；接近阈值分歧单列；不同切块不应产生系统性差异 |
| 性能 | TTFT、每块/端到端 P50/P95、吞吐、峰值显存 | 比较 1k/4k/8k/16k token、并发 1/8/32、块大小 1/8/16/32；不能只测短输入并发 1 |

detected_at 使用审查模型真正触发位置；decidable_at 是标注的首次可判定位置。提前报警单独统计，不能全部当正确早发现。以句标注的公开基准仍按其官方协议计算，再另报自定义 lag，不混淆不同起点。漏检不从延迟分母中悄悄删掉，至少同时给出 Recall-by-token-budget 曲线与检测者条件延迟。

静态“当前消息最终标签”和流式“是否应释放这一段”是不同任务，允许定义不同聚合器；比较缓存正确性时必须对同一前缀、同一聚合器，不能把已读全文的模型与只读前半段的模型硬比较。

置信区间按原始对话/问题分组 bootstrap，避免把同源前缀当独立样本。稀有事件或零错误同时给出二项区间/上界与样本数；展示 micro、macro、最差类别，不能只报 overall accuracy。最终阈值只在 calibration 上定。

**10. 训练阶段与消融**

| 阶段 | 操作 | 进入下一阶段的条件 |
|---|---|---|
| P0：数据契约 | 政策 v1、来源许可、字段映射、2k 金标样本、切分/去重 | 标注分歧解决；没有未知许可数据混入；测试隔离可追溯 |
| P1：基线 | B0/B1/B2 全部完成静态核心评测及流式回放；测硬件 | 得到 baseline.json、预测文件、错误切片和实测吞吐 |
| T1：静态适配 | 20k 起步，用输入/输出绝对标签训练；原生头保留，新头先 warm-up | dev 在相同误拦约束下优于 B1，或明确定位数据不足 |
| T2：政策与困难正常样本 | 增加政策边界、正常反例、多轮数据至约 50k | 目标类别收益存在，正常政治讨论等切片不退化 |
| T3：流式训练 | 加 prefix/片段监督，随机 chunk；逐级至 100k，规模按学习曲线决定 | 同时改善流式召回、误拦和 lag，静态能力不明显回退 |
| T4：校准与服务 | 冻结候选权重，在 calibration 定阈值，测试真 KV 缓存和输出缓冲 | 满足正确性、风险、延迟约束；再打开冻结 test 进行阶段验收 |
| P5：影子评测 | 获准真实流量只读旁路，去标识抽样与人工复核 | 风险与误拦可接受；形成具体灰度方案后再切换线上拦截 |

拟议损失：L = L_user + L_response + λ_category L_multilabel + λ_prefix L_prefix + λ_span L_span。只对存在标签的任务计算；按对话/监督位置归一化，防止长回答或大量前缀主导训练。全句违规标签不可广播给所有 token。span loss 是定位辅助，不能把某个词是否违规视作完全独立于后文上下文。

训练起始配置（需显存 profiling 后确定）：BF16；先 2k 上下文，再加入 4k/8k 长样本；0.6B 对照“LoRA rank 16 + 分类头”和全参微调。先固定一组保守配置（主干 LR 1e-5、分类头 LR 1e-4、warmup 3%、gradient clip 1.0、1 epoch），按有效 token 数设 batch 和累积梯度；这是待调起点，不是验证过的最优值。资源允许时试 2 epochs，依据 dev 早停。

第一轮只比较 T1/T2/T3 的逐项增益，再做必要消融：移除困难正常样本、移除前缀监督、去掉历史、移除词库信号、原生 Guard vs 通用主干初始化。固定训练数据/更新预算比较，避免把更多训练量当结构收益。入围方案以 3 个 seed 复跑；先用 dev 选最优，再在 calibration 校准和冻结 test 验收。

教师模型可用于候选标签和样本筛选；使用其输出前确认许可。第一版不把教师解释全文蒸馏给在线模型，也不把教师自报概率直接当真实概率。不安排在线 RL 或收费 API 批量调用作为默认前置条件。

**11. 两张 L20 的使用与排期**

用户描述集群有两张 L20，但 GPU 数量、空闲显存和拓扑尚未由 Kubernetes/nvidia-smi 核实。当前本地网络可到集群 API，现有凭证缺少已测试的 nodes 列表、跨命名空间 pods 列表以及 default 下 Pod/Job 创建权限；其他命名空间权限尚未全面核实。GPU 训练依赖可用命名空间、GPU 调度权限、镜像拉取和存储条件落实。

资源落实后，优先每卡独立实验：卡 A 做 0.6B 训练/消融，卡 B 做基线/评测/4B 复核性能测试。性能报告时不要让训练和被测推理同时抢占同一 GPU。不默认做跨机 DDP。先测 200–500 个 step 的实际 tokens/s、显存与 I/O，再估算全程；4B 的显存与 LoRA 可行性同样以实测为准。

建议按工作包推进而不承诺固定训练天数：

1. 先完成标签表、来源 manifest、数据适配器、2k 标注和冻结切分方案；许可不清的来源暂不进入训练。
2. 访问条件就绪后跑 B0/B1/B2 与硬件 profiling，产出第一份真实基线报告。
3. 做 20k 静态 pilot；没有改善时先查标签、分布和阈值，不直接堆数据或扩模型。
4. 通过后扩到 50k，增加多轮/困难正常样本，再做流式训练与 100k 学习曲线点。
5. 校准、冻结验收、影子评测。用户数据接入及线上拦截作为独立交付步骤执行。

**12. 实验记录与交付清单**

每次运行保存：代码 commit、基座 revision、数据 manifest/hash、许可轨道、政策版本、切分版本、随机种子、样本数/有效 token 数、超参数、checkpoint、tokenizer 与模板版本、量化方式、硬件、耗时、峰值显存、逐例预测和聚合指标。训练过程每 0.25 epoch 做轻量 dev，阶段结束做完整 dev；公开冻结 test 不随每个 checkpoint 反复跑。

观测面板最少包含四张图：Recall–FPR 曲线、各类别/角色误差矩阵、Recall–检测 token 预算曲线、延迟–吞吐–显存曲线。配套 20k/50k/100k 学习曲线和 calibration 可靠性图，能够看出“更多训练是否有效”和“增加速度是否牺牲安全”。

| policy_v1.md | 标签与动作规范、允许情形、仲裁例 |

| model_card.md | 可用场景、不支持范围、已知误差、上游及训练数据限制 |
| moderation_service | batch/stream 统一契约、KV 状态、缓冲及错误处理 |

当前最优先的可执行工作包是“2k 自有金标 + B0/B1/B2 统一评测框架”。先得到可信的基线和误差分布，再启动第一轮训练。
