# 起点重定：用裁判在分句边界上二分（T010 / T019）

v14 的违规起点是生成模型自己用逐字引用标的。T002 的 20 条分歧里有 18 条是起点问题：顺从式回答在引用之前就已经答应并着手去做（起点标晚了），或者把“接下来可以这样发”一类转折句当成起点（标早了）。起点决定前缀训练的标签：起点之前的位置是 safe，之后是 unsafe。所以起点不准，会直接变成训练噪声，尤其影响第六轮要解决的前缀误报。

## 做法

- 切点：回答里每个分句标点（。！？；，、.!?;:：和换行）之后的位置，再加上全文结尾。
- 有害内容一旦写出，更长的前缀仍然有害。所以先确认整段是 unsafe，再对切点二分，找到“写完这一句就变成 unsafe”的第一个分句，记为 `(prev_cut, cut]`。
- 定位后再多问一次下一个分句，它也必须是 unsafe。二分只看得到自己问过的前缀，这一步用来发现裁判不稳定（非单调）的情况。非单调的结果单独标出，不使用。
- 每条回答约需 log₂(分句数) + 2 次裁判调用。
- 裁判就是 judge v3.2（`flow/pipeline.py` 和 `flow/taxonomy.py` 是 `judge_v3/flow/` 的逐字节拷贝，单测会检查两者是否一致）。裁判只看到提问和回答的某个前缀，不知道 v14 起点，也不知道任何标签。

## 文件

| 文件 | 作用 |
|---|---|
| `flow/onset.py` | 切点和二分逻辑（纯函数） |
| `flow/flow.py` | Aster flow：一个 Task 放多条回答，逐条二分 |
| `make_onset_tasks.py` | 从 Run A 的不安全回答中按槽位（顺从 / 跑偏）和语言均衡抽样；只发送提问和回答，v14 起点留在本地答案表 |
| `extract_onsets.py` | 与 v14 起点对比：`v14_late`（v14 引用开始时，有害内容已经写出）/ `v14_early`（v14 引用结束时，裁判还没看到有害内容）/ `overlap` |
| `test_onset_cpu.py` | 6 项 CPU 单测 |

## 用途

pilot 先量出 v14 起点偏差有多大、偏向哪边。偏差大，就对 Run A 训练集全量重定起点，作为第二阶段（主干训练）的前缀标签；偏差小，就保留 v14 起点加缓冲区。
