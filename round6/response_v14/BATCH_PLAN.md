# v14 正式造数：Run A（5 万）+ Run B（其余全量）

2026-09-24，用户确认：两个 Run，A 并发 285，B 并发 150；模型 gpt-5.6-luna，每个 Task 最多尝试 1 次，重复 1 次。flow 按 v14 pilot（aster-dev-275）原样冻结，SHA 记录在各批次的 `manifest.json` 中，提交后会下载平台快照做逐字比对（`submit_batch.py`）。

## 词池

来源是 aster-dev-272 全量提取（`round2/oneword2_v12/full_snapshot_final_v2`：449,575 个词全部取回，其中 368,019 个中英两句都合格）。排除 round4/round5 数据和两次 pilot 用过的词后，剩 361,599 个词。按词族（NFKC + casefold + 去掉空白和标点）每族只取 1 个词，得到 **340,883 个词族**。词族只合并规范化后完全相同的写法，别名和近似重复没有合并。

| | Run A `batch_50k` | Run B `batch_rest` |
|---|---:|---:|
| 词数 | 50,000 | 290,883 |
| 分配方式 | 按类别平方根比例分配：21 个小类别全取，大类别按比例封顶（直播类只取 7.9%） | A 之外的全部 |
| split | train 46,998 / dev 1,509 / calibration 1,493 | 全部 train |
| 风险提问语言 zh / en | 24,701 / 25,299 | 124,664 / 166,219 |
| Task 数（每个最多 150 词） | 352 | 1,943 |
| 预计 token（输入 / 输出） | 约 1.5 亿 / 0.36 亿 | 约 8.8 亿 / 2.1 亿 |
| 预计耗时 | 约 5 小时 | 约 30 多个小时（并发 150） |

两个 Run 的 task_key、词族互不重叠。dev/calibration 词族另外排除了与旧数据词族同形的写法。

## 切片

最初每个 Task 放 300 词（instruction 约 208 KB），上传时第一个归档就被拒（非 Aster 信封的 HTTP 400）。实测 196 KB 能传、208 KB 被拒，因此改为每个 Task 150 词（instruction 不超过 109 KB）。改切片后逐条比对：选词、split、rotation 与 300 词版本完全一致。

## 用于训练时的过滤（下游执行，不改 flow）

1. 只用 4 条回答全部合格的词，保持每个词的 2×2 平衡。
2. 剔除“要求先铺垫但起点为 0”的回答，剔除后该词按不完整处理。
3. `quality_flags` 只做统计。
4. 训练抽样时再按类别和风险提问语言重新平衡（Run B 本身在语言上不平衡）。
