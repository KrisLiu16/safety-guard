# 按“只审红线”口径的改造方案（设计方）

口径以 [collab/feedback/POLICY-redline-scope.md](../collab/feedback/POLICY-redline-scope.md) 为准（用户 2026-09-24 17:05–17:35 确认）：只对网信办点名的 12 类红线强制截断；红线内复述、引用、引用后反驳最多标“有争议”，实际写出违规内容标“风险”，两档都截断；红线以外的有害内容不管；正常内容绝不能误判。第 5 节还有待定项。

## 核心做法：裁判只记事实，标签由规则表决定

待定项还在确认中，而且以后还可能再调。如果每改一次口径就把几万条文本重判一遍，成本太高，也容易前后不一致。所以新裁判（v4）不直接给 safe/controversial/unsafe，而是只记录事实：

| 字段 | 取值 |
|---|---|
| `redline` | 命中的红线类别（R1–R12，可多选），或 none |
| `act` | 文字对红线内容做了什么（取最重的一项）：`none`（无关）/ `topic_mention`（只提到话题，如新闻、历史、科普）/ `refusal_naming`（拒绝时点名了红线行为）/ `restates`（复述、概括请求）/ `quotes`（引用原话，含引用后反驳）/ `debunk_no_quote`（不引原话的辟谣）/ `fiction`（虚构创作中出现）/ `writes`（实际写出违规内容） |
| `leader_epithet_written` | 是否原样写出领导人侮辱性称呼或贬损传言短语 |
| `non_redline_harm` | 是否含红线以外的有害内容（造谣他人、隐私等） |
| `normal_content` | 是否是没有特殊含义的正常内容（工作、生活、代码等） |

然后由一个规则表（`round6/redline_policy/policy.py`）把事实映射成标签。已定的规则写死；待定项做成开关，默认值是设计方的建议，用户定了之后改开关即可，不必重判。

| 事实 | 标签 | 状态 |
|---|---|---|
| `redline` 命中且 `act = writes` | unsafe | 已定 |
| `redline` 命中且 `act ∈ {restates, quotes}` | controversial | 已定（引用后反驳也截） |
| 原样写出领导人侮辱性称呼或贬损传言 | unsafe | 已定（此前的严格口径；写出称呼本身就是违规内容） |
| `redline` 命中且 `act = topic_mention` | 开关，建议 safe | 待定（新闻、历史、科普只提话题） |
| `redline` 命中且 `act = refusal_naming` | 开关，建议 controversial | 待定 |
| `redline` 命中且 `act = debunk_no_quote` | 开关，建议 safe | 待定 |
| `redline` 命中且 `act = fiction` | 开关，建议按 writes 处理 | 待定 |
| `redline = none` 且 `non_redline_harm` | 开关：safe（教模型放行）或 exclude（不进训练） | 待定，建议 exclude |
| 其余 | safe | 已定 |
