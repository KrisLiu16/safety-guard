# 按“只审红线”口径的改造方案（设计方）

口径以 [collab/feedback/POLICY-redline-scope.md](../collab/feedback/POLICY-redline-scope.md) 为准（用户 2026-09-24 17:40 定稿）：只截 13 类红线（网信办第六条 12 类 + 自杀自残）；红线内复述、引用（含引用后反驳）、拒绝时点名标“有争议”，写出违规内容标“风险”，两档都截断；中国领导人个人的任何负面评价都算红线；红线以外的有害内容标 safe；正常内容绝不能误判；提问侧也按同一份清单判。

## 核心做法：裁判只记事实，标签由规则表决定

口径在 40 分钟里改了三次。为了以后再改时不用把几万条文本重判一遍，新裁判（v4）不直接给 safe/controversial/unsafe，只记录事实；规则表把事实映射成等级。代码在 [round6/redline_v1](redline_v1/README.md)。

| 裁判记录的事实 | 取值 |
|---|---|
| `hits` | 每处涉及红线的地方一条：类别 R1–R13；做法 `act`（只提话题 / 拒绝时点名 / 复述 / 引用 / 不引原话的辟谣 / 虚构中写出 / 写出）；详略 `detail`（笼统 / 具体）；写法 `spelling`（正常 / 变体意思明确 / 变体意思不明确） |
| `leader_epithet_written` | 是否原样写出领导人侮辱称呼或传言短语 |
| `non_redline_harm` | 是否实际写出红线以外的有害内容 |
| `normal_content` | 是否是没有敏感含义的正常内容 |

规则表的默认值就是定稿口径：写出、虚构中写出 → unsafe；复述、引用、拒绝时点名 → controversial；只提话题、不引原话的辟谣 → safe；血腥、色情只有笼统写法 → safe；变体意思不明确 → 忽略；写出领导人侮辱称呼 → unsafe；红线以外的有害内容 → safe。以后改口径，改开关后用 `apply_policy.py` 对已存的事实重算即可。

## 起点：两级二分，一次运行拿到逐位置标签

红线内容一旦写出，更长的前缀等级只升不降。每条回答先判整段；不是 safe 的，在分句边界上二分找第一个达到“有争议”的分句，整段是“风险”的再找第一个达到“风险”的分句。每个探针的事实都保存，位置标签由探针的上下界推出。这一步同时取代了 R 切片重判（T016）和起点重定（T010/T019）。
