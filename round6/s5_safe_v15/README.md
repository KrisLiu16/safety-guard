# S5 安全那一半：长篇安全思考（T011）

用户已定（2026-09-24）：线上要审核模型的思考过程，所以要有长流数据。本目录只做 S5 **安全**的一半。危险的那一半与 S1 一样，生成指令由团队成员编写，见 [collab/BOARD.md](../../collab/BOARD.md)。

官方 thinking 集上的误报，集中在“复述有害请求、但最后安全处理”的思考中段（[decision_rule](../decision_rule/RESULTS.md)）。这里每个词写两段 500–1,500 token 的第一人称思考，全部是 safe：

| 思考 | 对应提问 | 内容 |
|---|---|---|
| `risk_reasoning_long` | 该词原有的 unsafe 提问（取自 Run B 种子，不改写） | 概括复述请求（可以原样提到这个词），分析风险和后果，决定不提供有害帮助，规划安全回应。任何位置截断都必须安全：只概括请求，不写出有害内容、细节或话术，也不先写后否定 |
| `helpful_reasoning_long` | 该词原有的 safe 提问 | 理解提问，梳理知识，规划有帮助的回答 |

- 思考的组织方式由程序轮换分配（分步骤、多种理解、打草稿再修正、按法规逐项检查），避免千篇一律。
- 这里不生成新的有害内容：有害提问沿用 v12 已有的提问，模型只写安全的思考。
- 立场按国内口径；如果这个词本身是对国家领导人的侮辱性称呼，返回 skip。
- 词族划分与 S2 使用同一条规则和盐值，所以同一个词族在两个切片里属于同一个 split。自动排除 S2 pilot 已用过的词。
- 生成用 DeepSeek，复核用 luna 上的 judge v3.1。被判为 unsafe 或 controversial 的直接丢弃。

| 文件 | 作用 |
|---|---|
| `flow/pipeline.py` | 提示词、schema、两种接口的请求体、程序校验（长度：中文 700–2,400 字，英文 380–1,400 词） |
| `flow/flow.py` | 与 S2 的 flow 相同，只改了说明文字 |
| `make_pilot.py` | 从 Run B 种子按来源组轮流抽词，每个词一个 Task |
| `extract_s5.py` | 下载归档并重新校验，输出 v14 行格式的 `examples.jsonl` 和长度统计 |
| `test_s5_safe_cpu.py` | 6 项 CPU 单测，包括与 S2 的词族划分一致、与 judge_v3 构建器兼容 |

已知的局限：judge_v3 的构建器对每条安全文字只取整段和一个中段前缀。对 1,500 token 的长文来说，前缀抽查偏少。pilot 先这样跑，放量前再决定是否增加前缀切点。
