# 固定窗口文本流加速交付

本目录是独立的后续推理实现；不修改已冻结验证包、训练数据、模型权重或质量优先候选。

质量优先候选仍为 full 架构的 classification_rl，SHA 29fc3e5663eaa333235b1c2ba84d4c0a964f6ece4fd146c9fc6ec01761eaf222。
低延迟候选固定使用已训练、通过 8K 长流检查的 window/SFT，SHA bb16a3a6f87748ce302d6db125822b31add9a7d5210cd44804d9416be44f30d2。不按保留测试重新选权重，不追加训练。

动机：既有 W512、batch=1、8-token CUDA Graph 实测 1424.50 ITPS / P95 5.63ms，对同权重 eager 的 339.79 ITPS / 23.65ms，数值、回滚种子和会话隔离检查通过。该实验尚未成为文本接口；本阶段将实际文本分词/回滚接口接入，并对 1..32 个 token 的精确输入长度预捕获。较短前缀和大块 prefill 使用原 eager 路径。

初始化先用独立合成种子捕获全部 32 个长度，记录启动耗时与共享 arena 的真实存储/显存；用户请求中不隐藏冷捕获的额外模型计算。每次 replay 返回独立完整缓存，继续使用已有事务/快照机制；输入 ITPS 仍只计新增输入，零生成 token。

验收必须覆盖所有长度、完整/分块一致性、真实 BPE 收缩、回滚、角色切换、并发会话隔离、失败事务、8192 上限、128 次同轨迹实际文本性能、独立便携加载和原模型概率对齐。容差和风险标签不变。没有全部实际通过就不作为可用加速入口交付。

同一验证任务另外补跑原验证中未完成的两项检查，原 v1 产物保留：质量候选 full/RL 与官方 A0 均用 benchmark v2（初始 512/4096 token、每组预热及计时各 128 块、块长 1/8/32、最终不超过 8192），分别使用 modern 与 legacy 环境。新结果在 `baseline_recheck/speed_candidate_v2.json` 和 `speed_a0_v2.json`；只能配对同协议、同物理 GPU UUID 的结果。该对照使用各自现有分类运行时，A0 额外计算另一角色分类头，不把全部速度差归因于注意力结构。

window 与 full/RL 两次词表诊断都显式读取 `keyword_tokenizer_compatibility_v1.json`。该证明已在真实 modern CPU 环境逐条核对原 1024 条 token IDs，未加载神经模型；范围仅限这批冻结输入，不代表两份 tokenizer 原始 JSON 全局等价。继续使用原 IDs、标签及各自已有阈值，不重建数据或重调阈值。原主候选 manifest、两候选 calibration/summary 都列入外部输入哈希检查。

`python prepare_fast_package.py --check-only` 只校验源码、固定候选、冻结数据及证明的哈希关系，不创建包。随后运行不带此参数的命令才冻结独立包，拒绝覆盖已有包或 manifest。调度含 8 个串行必需阶段，阶段超时合计 **8100 秒**，另需留启动、依赖安装和结果收集时间。三个补跑阶段均为 600 秒，日志及结果放在 `baseline_recheck/`。
