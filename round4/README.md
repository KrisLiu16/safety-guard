# 第四轮：风险指标驱动的分类训练

2026-09-23。用户明确要求打开思路，以是否识别风险为目标；教师相似度不再作为主要训练和选模目标。原版 Qwen3Guard 是安审教师，但其标签和最近训练的 H24 都不作为能力上限。


当前已冻结 [risk_v2 数据清单](data/risk_v2/manifest.json)：33,311 条训练记录，单 epoch 3,733,035 个输入 token；其中公开参考 20,000、同词弱标签 8,192、benign rubric 4,096、长背景弱标签 1,023。三组各 4,164 次优化更新，之后对选出的候选执行 256 次分类 RL 更新。912 个已完成 Aster 分片已完整取回，包含 488,560 条格式合格例句和 221,694 个完整中英词对，见[产物核验](../round2/oneword2_v12/completed_snapshot_v2/audit.json)。

新增记忆网络已在 L20 通过组合前向/反向、非零门控的完整/分块一致性与因果检查；实际总参数 753,554,823，新增 98,352。结构检查通过不等于风险能力已提升，见[数值检查记录](memory_smoke.json)。

## 三个同预算候选

1. **full：**完整 H24 主干 + 已训练风险头。
2. **window：**全部 24 层保留，6 层注意力按 2048→1024→512 逐步缩小窗口。
3. **memory：**同样的窗口课程，另外增加可学习的压缩历史记忆。窗口外键值进入固定矩阵与归一化状态；当前 query 通过学习得到的特征映射读取，和局部注意力通过可训练门融合。新增约 10 万参数，仍小于 1B。

第三个候选解决“窗口以外的信息无处直接读取”的问题，不预先承诺更快或更准。它保留 18 层原 GDN，再在 6 个注意力层增加记忆。缓存仅为研究版 token-ID 路径，文本重分词回滚和生产调度另验收。

训练状态的实际检查：第 1536 步，6 层共 48 个记忆门值均已从零变为非零，18 个新增参数张量的优化器一阶矩也均为有限非零值，见[参数更新证据](memory_parameter_update_audit.json)。这确认记忆支路在学习；它不代表风险质量已提升，也不代表最后按开发集选择的导出权重必然来自该步。前 1041 步使用 W2048，训练组尚未触发窗口外记忆，最早可触发的是第 1064 步，见[训练覆盖核对](memory_training_coverage.json)。

局部注意力结合线性历史记忆的思路参考 [LoLCATs](https://arxiv.org/abs/2410.10254)；本轮不照搬其教师匹配目标或 LoRA 训练方案。记忆核使用 [FLA 0.5.2](https://github.com/fla-org/flash-linear-attention/tree/v0.5.2/fla/ops/linear_attn)，矩阵运算为 BF16、累计归一化为 FP32，防止长历史中小增量被 BF16 舍入吞掉。保存状态时去掉整块 cumsum 底层存储的意外引用。

## 数据与明确的安全反例

公开来源风险训练样本扩到 20,000 条，覆盖中文用户、中文助手和英文助手；加入 Aster 已完成分片的同词中英安全/风险弱标签对，以及程序构造的有限范围 benign rubric 样本。Aster 并发 400 是用户在平台调整并确认的运行设置；本轮提取不新增生成请求。

benign rubric 包括中立背景询问、把词语当作引用文本处理、风险请求后的安全拒绝、无害的文字处理回答。它们含有词库词，不能因命中词而判风险。引用也不是通用免责条件：实际提出威胁、诈骗、隐私侵害等行为的样本仍按行为标签判断。

来源标签按各来源政策解释；Luna 标签保留未验证身份并降权。合成背景拉长只作为低权重压力样本，不冒充自然长程安审金标。原 v12 两句生成格式及原始产物不变，新增的是独立下游训练视图。

校准 900 条、开发 1,200 条、另保留本轮独立保留的测试 1,200 条（排除当前 H24 训练词族及此前测试 ID，不声称排除所有历史项目语料处理），公共 prompt family 互斥。合成词的配对和 benign 派生共享同一词族。做精确文本去污染，不声称已经排除语义近重复。公开参考测试仍缺英文用户分组，这一能力不能宣称独立验收完成。

## 主训练和选模

- 三组使用相同的冻结数据与初始 H24 权重，2 个 epoch，microbatch 4、有效 batch 16。
- 损失是带来源权重的风险交叉熵；没有教师 hidden-state/cosine/logit 蒸馏项。
- 更新完整语义主干和风险读出；记忆候选新增特征映射及门同时学习。类别头保留但本轮不做类别能力声明；第三档风险也没有新增独立硬标签。
- 每 512 次更新观察学习曲线，包含第 0 步作参照，不因单次跌分提前否定路线。
- 阈值只在单独校准集上按 5% 安全误报预算选取；开发评分为宏平均风险召回减去超出误报预算的惩罚，同时报告每组 PR-AUC、ROC-AUC、Brier、真实误报和漏报。它是研究选模规则，不是生产 SLA。
- 窗口候选统一以部署目标 W512 验证，避免用 W2048 的能力数字宣称 W512 已通过。
- 所有架构和检查点选择完成后才读取新的保留测试集。老官方子集仍可作回归，不能反复调参后称盲测。

## 分类 RL 的 rubric

监督训练后，对开发集选出的候选增加一个可比较的离散分类 RL 阶段：每个输入前向一次，从风险概率采样 4 个分类动作，不生成文本 token。

```text
判断正确：+1
无风险内容被判风险：-3
有风险内容被漏过：-4
```

这些是初轮实验成本，分别留日志，不仅报平均 reward。未验证标签的奖励按数据权重降低。用 REINFORCE、逐输入的精确期望奖励基线降低方差，并保留小比例监督项；KL 只约束相对本轮监督模型的更新幅度，不用另一个 LLM 的输出充当正确答案。RL 与 SFT 在相同开发/保留测试集比较，保留未更新版本，不因“做了 RL”就自动晋升。

这一阶段训练风险分类动作，尚不是完整 `allow/hold/block` 序列控制。后者仍需要可信风险证据位置和实际泄露/等待成本。

## 执行边界

全部模型前向、反向与正式性能测试在 L20。本机只处理 JSON、归档与分词。使用 `172.19.1.144` 的一张物理 L20，申请全部 8 个逻辑 time-slice 名额；没有修改共享节点配置。项目专属 PVC 从 20Gi 扩到 40Gi，容纳可恢复训练状态和候选权重。

工程检查包括：独立注意力数学参考、非零记忆门的完整/分块一致性、未来后缀不能影响过去表示、物理缓存大小上界、真实组合网络反向传播。通过后才进入风险训练。此前内核类型及状态视图问题作为实现错误修复，不当作架构质量结论。

### 训练后长流复核

执行中复查发现 `train_risk.py` 原有的 16 条开发样本流式门槛全部短于 W512，仅能证明短输入一致性。当前已加载的训练代码和冻结数据保持不变，另加 [postrun_long_stream.py](postrun_long_stream.py)，由结果收集器在训练、RL、A0 评测完成后、确认释放 GPU 前执行。它检查四份实际导出权重，在 513 / 1025 / 4097 / 8192 token 前缀处比较整段与两种分块顺序的风险概率，并检查窗口/记忆模型状态空间上界，两个角色头均覆盖。

补充检查使用开发集拼接文本，只验证数值和缓存行为，不把它当作长程风险语义金标，也不重新按保留测试集选模。`long_stream_audit.json` 中的失败必须单独保留；主流程 `completed` 只表示训练完成，不能覆盖该失败，更不能代表候选已获生产验收。原短流检查选出的 RL 候选若不通过长流检查，也不能晋升。全部检查仍在同一 L20 上串行执行。

### 端到端交付验收

主训练及上述后置检查完成、报告收集并释放首个 Job 后，另用同一节点/PVC 的一张 L20 运行 [validation_worker.yaml](validation_worker.yaml)。它验证实际文字分块接口、三个完整 Qwen3GuardTest 分片和便携模型包；当前该验证 Job 尚未提交，不和训练抢卡。

[text_stream_runtime.py](text_stream_runtime.py) 已实现文字追加、原生分词最长相同前缀、两份完整状态快照及回放。它处理追加字符使 token 数减少的 BPE 情况，失败事务不更新已有会话；长前缀按大块处理，只复制最终要保留的两个快照。20 项 CPU 状态机测试与原生 tokenizer 测试已通过，真实神经缓存的深拷贝/隔离/数值一致性待 L20 验收，见[文本流说明](TEXT_STREAM_USAGE.md)。新增净 token 与回放 token 分别计数，实际文本 ITPS 不把回放计为新增输入。

公开基准适配数据已冻结：thinking 1059、thinking_loc 569、response_loc 813，均无截断或排除。学生按训练角色格式和原生 token 的两连续风险判决评测，A0 按原官方模板评测；不套用原 Qwen3 的 token 位置注释。重叠分片不合并总分，loc 分片没有安全样本、不能估计误报率。候选只按已固定开发指标和长流门槛选择，完整公开基准留作后续观测。

最终候选与 A0 另用 [benchmark_pair.py](benchmark_pair.py) 在同一 L20 串行做效率对照：512/8192 初始上下文 × 1/8/32 输入块，每组独立状态完整预热后计时 128 次，保存每次延迟、CPU 可见风险概率、原生 token 计数和去重后的缓存存储。两边使用同一中英无害文本的各自原生分词，最长计时轨迹到 12288；这只是 token-ID 运行时对照，不扩大文本 API 的 8192-token 上限。只用这对同协议产物计算提速，旧的 24 次调用数字仍单列。该新增阶段不参与选模或训练。

便携交付代码由 [package_model.py](package_model.py)、[standalone_model.py](standalone_model.py) 和 [run_guard.py](run_guard.py) 组成：包内保存完整分类器、配置、分词器、窗口/记忆代码和依赖锁，加载时不需要原基座权重或旧训练目录。普通构造器初始化非持久 RoPE 缓冲区，随后加载完整权重；此独立加载路径仍须与旧 loader 在 L20 上逐项对齐，不能以打包成功代替验证。
