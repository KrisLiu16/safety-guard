# 第二轮数据与训练路线讨论稿

日期：2026-09-23。此文记录可检验的候选方案，不预设哪种模型胜出。

## 本次造数实验

MiMo 模型配置 `mdl_01M33V8C39GGNX33TFS5ETDNR3`（mimo-v2.6-flash）已通过 Aster 连通性测试。首批选 1,000 个未在前轮使用的词，宽松许可层和 Citizen Lab 非商业研究层各 500 个；按 22 个真实来源类别组织为 49 个 Task，每个 Task 最多 30 词并逐词串行请求。原 17 个 Vocabulary 文件只覆盖部分基础词，Citizen Lab 没有相同分类，因此不伪造主题标签。每词只请求一次，按固定十槽生成 7 中文、3 英文，共目标 10,000 条；Run 并发上限 50，最多尝试 1 次。来源记录与许可证保持在 task 和输出中。任务中的来源类别不是安全标签。

主批提示版本 `guard-mimo-bilingual-v4` 解决首轮出现的角色、标签、证据片段和前缀不一致问题：固定语言、角色、目标风险、输入标签与场景；同时要求可见的风险证据、前缀可判定点，英语文本只把中文词条作为带引号的专有词保留。中文 4 安全/3 不安全，英文 2 安全/1 不安全；覆盖用户问题、助手回答、拒答、引用/批评。安全政治讨论不得因为词命中而判风险。真实人物和机构的风险样本只能呈现造假/骚扰意图，不能编造具体犯罪事实。若词条无法自然入句，返回 unfit 而不硬凑。结构校验、去重、语义复核是三个不同状态，合成标签不直接视为金标。

Aster 已发布原 MiMo 分组数据集版本 `dsv_01M3685G5FS8XR18EDE39EH78W`。前 5 个词分两次检查（`aster-dev-257`、`aster-dev-258`），MiMo 对部分词返回 `content_filter`；主 Run `aster-dev-259` 因用户要求切换模型而停止。新配置改用 `gpt-5.6-luna`、并发 20，按来源分组与逐词串行调用不变。Luna 主批 `aster-dev-265` 处理首批剩余 993 词；失败提示版本 `aster-dev-263` 已停止，历史尝试保留。当前紧凑 v7 契约让程序添加固定槽位元数据，模型只填文本与证据，输出恰好十项。服务端拒绝、格式错误和未满十条分别计数；每个物理 Task 的 reward 是完整十条例词数除以该 Task 词数，类别 reward 用加权汇总计算。

全量 449,575 个文本词已按真实来源落入 33 类，详见 [全量索引](full-source-index/manifest.json)。Aster 每 Task 有 24 小时时限，最大来源类有 159,580 词，不能用一个串行物理 Task 装完；1,517 个物理分片只是时间预算分片，不增加逻辑类别。用户将全量并发改为 40，并要求直接启动、冻结格式；v8 一词真实检查原样 10/10、训练记录字段与 `guard-record-v1` Schema 一致后，全量 Run `aster-dev-267` 已提交。其 prompt、Schema、flow 和数据集摘要见 [冻结清单](contract_manifest.json)与[Run 清单](full_run_lock.json)。

首批抽样限制 2–12 个汉字；Citizen Lab 新增项还要求在至少两个来源家族出现，以减少乱码词任务。这个限制仅用于预算受控的首批实验，不改变完整 449,575 个任务种子。以后扩大覆盖应按词类、长度、来源、主题和难度分层，不能只增加纯随机词。每词十条会让同词样本高度相关；划分 train/dev/test 必须按词族、别名和生成模板隔离，而不能按句随机划分。

批次验收：记录任务成功率、每词完整十条率、结构有效率、英语语言合格率、去重率、safe/unsafe 证据一致性和抽样语义分歧率。追加无词命中样本、真实对话和中立公共事务样本，防止模型只记词。长期若全部 449,575 个词各生成十条，理论上是 4,495,750 条、449,575 次模型请求；并不等于同样数量的独立、高质量训练样本。

本次十槽是安全/风险两端的上下文对照，不覆盖 Qwen3Guard 原生的 `Controversial` 中间类。后训练时不得把原三分类头当成二分类直接覆盖；应保留原类，在独立边界样本与教师软分布中恢复中间类，并单独报告中间类的校准与滥用率。用抽象占位避免捏造指控会造成模板重复，必须给表达模板设权重/近重复过滤，并以真实语境补足。

## 训练的四个可比较分支

1. **B0：冻结的原版 0.6B Stream。** 在官方 Qwen3GuardTest 与项目独立中文集上记录用户/回答分类、前缀定位、误拦和延迟。这是所有新方案必须超过的起点。
2. **S：直接后训练 0.6B。** 使用经质量分层的样本做小规模分类头/LoRA 监督训练，保留原能力的 KL 或蒸馏约束。分类动作只有三类时，标签交叉熵和软标签 KL 通常比纯策略梯度更直接；上一轮有限动作 RL 对官方基准有轻微退化，不能把“RL”当作质量保证。其后若要优化放行/暂挂/拦截的流式时机，可把实际时延与误拦成本构成序列决策奖励做 RL。
3. **T→S：冻结 4B 教师蒸馏到 0.6B。** 先用公开的 Qwen3Guard-Stream-4B 作为教师，对相同可见前缀给出风险/类别软分布，再训练 0.6B。只在教师经独立中文金标确认优于学生的子分布上提高教师权重；教师与 MiMo 初标分歧、低置信度样本进入校准/仲裁池。输入与回答分别蒸馏，绝不把未来 token 给前缀教师。
4. **T*→S：先后训练 4B，再蒸馏。** 仅当 T→S 仍存在明显质量缺口、且 L20 试验确认 4B 训练/推理成本可接受时执行。4B 教师也可能过拟合合成词条并把偏差传给 0.6B，因此必须比较同数据预算下 S、T→S、T*→S 的独立测试表现与最终 0.6B 推理成本。大教师不是自动增益。

我的当前优先级是 B0 → S 与 T→S 并行对照 → 再决定 T*→S。0.6B Guard 已继承 Qwen3 的语言理解能力，少量域内数据用于迁移和校准；从零训练新分类网络需要重新获得这种能力，所需语料远多于词库例句。Jev 可借鉴的是“直接输出结构化概率、不生成答案 token”的任务形状；TypeSafe 官方只公开了高层设计和 RLCD 名称，没有足够细节复现其生产权重或内部架构。

## 更快的流式分类器实验

第一条性能线使用原版稠密主干：正确增量 KV 缓存、块内逐 token 分类、批调度、权重量化与模型/词表版本隔离。这些改造必须在等质量下报告首判延迟、续流 P50/P95/P99、并发吞吐、显存/每会话 KV、缓存命中率和误拦/漏判；不能仅报单请求 token/s。上一轮在 M5 上最大确定收益来自修正增量缓存，而不是换网络结构。

第二条才是 Jev 式专用判别架构：保留预训练编码能力，尝试浅层因果学生、轻量决策头、按消息角色多头输出与早退。若使用双向编码器，全量输入分类可能快，但流式缓存需要重算已见词，不能默认比因果模型便宜；从头训双向网络也会失去现有语言能力。MoE、MLA、DSA 等机制仅在 L20 上的真实瓶颈和相应 kernel 支持表明净收益时进入实验，不因新颖性优先。

## 数据和评测边界

Qwen 官方技术报告称其训练使用约 119 万条人标与合成样本，公开仓库当前提供模型、论文和评测代码；公开的 Qwen3GuardTest 是测试集，并非那 119 万条训练语料。报告说明 Gen 使用 SFT、自动标注和标签蒸馏；Stream 用因果主干加用户/回答分类头，并结合 rollout 与判别器定位危险起点，风险与类别用交叉熵训练。可复用这些方法，但不能把官方测试集混入训练。[官方技术报告](https://arxiv.org/html/2510.14276) · [官方仓库](https://github.com/QwenLM/Qwen3Guard) · [官方测试集](https://huggingface.co/datasets/Qwen/Qwen3GuardTest)

正式能力门槛需有独立中文集，尤其覆盖正常政治讨论、新闻/历史、直接批评、引用反驳、隐喻、跨轮指代、用户危险提问后安全拒答，以及回答中途才变危险的情形。Qwen3GuardTest 用于通用回归与流式位置对照；其中两个定位分片是风险样本，不能单独估算误拦率。开发集上校准阈值，冻结测试集只在里程碑评测；报告 family bootstrap 区间。Citizen Lab 层的 CC BY-NC-SA 4.0 来源标记及非商业研究边界应保留在词表与生成样本中。
