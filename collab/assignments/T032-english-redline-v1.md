# T032 英文红线数据 v1：Aegis 2.0 训练集，用我们的红线裁判重标

- 版本：v1（2026-09-25）
- 设计和执行：执行方（兼设计）。
- 代码：`round6/english_redline_v1/make_rows.py`；拆分统计 `round6/qwen3guard_bench/redline_subset.py`。

## 起因

Qwen3Guard 英文基准上，第二阶段 v1 的英文红线召回比第五轮低很多（阈值 0.5）：

| 红线组 | 提问：第五轮 → v1 | 回答：第五轮 → v1 |
|---|---|---|
| 武器、毒品（第 12 条） | 88.6% → 37.0% | 97.9% → 61.7% |
| 自残（第 13 条） | 79.3% → 29.3% | 100% → 56.5% |
| 色情（第 11 条） | 95.0% → 21.9% | 94.7% → 12.0% |
| 暴力（第 2、7 条，类别比红线宽） | 94.3% → 25.9% | 100% → 34.2% |

- 安全样本的误报：提问侧 32.0% → 2.7%，回答侧 53.7% → 4.3%。
- 非红线有害：提问侧 80.6% → 8.2%，回答侧 93.6% → 11.5%。这部分下降是口径决定的，符合设计。
- 原因：第二阶段的训练数据几乎全是中文，全参数训练后英文红线能力退化了。

## 数据

- **来源**：nvidia/Aegis-AI-Content-Safety-Dataset-2.0 的 **train** 集。
  - 许可 CC BY 4.0，不是 gated；
  - 版本钉在与基准相同的 commit；文件 SHA 记在 manifest。
- **剔除**：
  - 已脱敏（REDACTED）的提问、空文本、超过 6,000 字符的文本；
  - 提问或回答与基准任一条消息完全相同的行，保证基准不被训练污染。
- **抽样**：按红线组抽，组内用哈希定序，结果固定。

| 组 | 提问 | 回答 |
|---|---|---|
| weapons_drugs | 1,300 | 570（全部） |
| self_harm | 327（全部可用） | 66（全部） |
| sexual | 800 | 385（全部） |
| violence | 800 | 400（全部） |
| other_harm | 700 | 600 |
| safe | 800 | 900 |
| 合计 | 4,727 | 2,921 |

- **划分**：按 Aegis 行号做哈希，dev 5%、calibration 5%、其余 train。同一行的提问和回答在同一份里。

## 标签

- Aegis 的类别只用来抽样。训练标签来自我们的红线裁判 v4.2 和 apply_policy v1.4，所以口径与 POLICY 一致：
  - 其他有害按警觉档处理；
  - 与政治因素组合的按风险处理。
- 裁判流程同 Run A：先用 DeepSeek，失败的样本用 luna 补判。
  - 回答：aster-dev-379，293 个 Task；
  - 提问：aster-dev-380，237 个 Task，`--target user`。
- 标签输出到 `labels_v2_alert/en_redline/`（回答）和 `labels_v2_alert/en_redline_prompts/`（提问）。

## 训练接入（T030 v2）

- `build_targets.py --extra SOURCE ROLE ROWS LABELS`，来源名 `en_redline`（回答头）和 `en_redline_prompts`（提问头）。
- 混合比例：`en_redline/assistant=0.5`、`en_redline_prompts/user=0.5`。

## 通过标准（v2 在基准上，阈值 0.5）

- 四个红线组的英文召回：提问侧每组 ≥ 70%，回答侧每组 ≥ 80%。色情一组例外：Aegis 和 BeaverTails 的色情类包含性暗示，POLICY 不管，所以只报告，不设门槛。
- 安全样本误报：提问侧 ≤ 8%，回答侧 ≤ 10%。
- 中文红线评测（T029 的做法）的 AUC 比 v1 下降不超过 0.02。

## 反馈里报告

- 裁判的 run_no、失败数、补判数；
- 标签按组 × 级别交叉（只报计数）；
- v2 在基准上的整体 F1 和按红线组拆分的数字。
