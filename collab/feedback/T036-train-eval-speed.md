## 训练

- v4 每步 0.82 秒里 84% 是和 token 数无关的固定开销：每步拆 4 次前向，每次前向加反向固定约 0.16 秒；
  每步启动 33,333 个 kernel，CPU 等 GPU 177 次（共 229 毫秒）。
- 同一批 152 组真实数据：现状 0.854 秒 / 组（5.9% MFU）→ 一组一次前向 0.468 → 再关检查点 0.359 → 再批量 loss 和 fused AdamW **0.242**（20.8% MFU）。
  与现行训练步的梯度余弦 ≥ 0.9993（同一步重跑 ≥ 0.99993），loss 相对差 ≤ 2e-4。
- 上限：L20 大矩阵乘 116.8 TFLOPS；按本模型的层形状，每次前向 2,048 token 以上矩阵乘到 104–109 TFLOPS；整个前向加反向当前实现最多 36% MFU。
  剩下的时间主要在 dtype 转换和 fp32 逐元素小算子（约 41%，矩阵乘约 31%），下一步是 torch.compile 融合和 bf16 计算权重，不是加大批量。
- 关检查点后，一次前向 16,384 token 放不下（8,192 token 峰值 26.9 GB），所以一次前向上限定为 8,192。

## 评测

- 4 进程：提问侧 253 → 124 秒，回答侧 2,023 → 616 秒；卡的利用率 23% → 约 90%。
- 发现：FLA 的 Triton kernel 在每个进程里各自自动调优，几种配置快慢相近，谁胜出看计时噪声，而不同配置的舍入不同。
  单独一个进程两次也可能选得不一样（l2norm 的 BT 8 或 32）。所以现在固定一张配置表 `autotune_l20_v1.json`：
  4 进程、8 进程、重跑逐行相同。
- 没固定时的 v4 单进程评测落在另一种配置上；换成固定表后，各项流式 AUC 到小数点后三位相同，阈值规则的比例差不超过 0.1 个百分点。
  从 v5 起，评测一律用 4 进程和这张表。
