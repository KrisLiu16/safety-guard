# 协作约定：设计方与执行方通过 main 分支交流

2026-09-24 起生效。三方分工：

| 角色 | 是谁 | 负责 | 不做 |
|---|---|---|---|
| 用户 | 项目负责人 | 定方向；定并发、放量、是否提交 Run、是否开始训练 | — |
| 设计方 | 云端 Claude（碰不到内网） | 计划、代码、流程模板、作业 yaml、验收标准；读反馈后决定下一步 | 不跑 GPU、不操作 k8s 或 Aster；不写 S1 违规内容的生成指令 |
| 执行方 | 本机 agent（有 kubectl、Aster、Mac 上的数据） | 按任务单执行，把结果写成反馈 | 不改设计、不自行扩大任务范围；Mac 上不跑模型（推理、训练都放 L20） |

## 沟通渠道：只用 main

- 设计方把任务单写在 `collab/assignments/Txxx-<短名>.md`，状态总表是 [BOARD.md](BOARD.md)。
- 执行方把反馈写在 `collab/feedback/Txxx-<短名>.md`，文件名与任务单一致。
- 任务单修订后版本号加一。执行方发现任务单版本高于反馈里记录的版本，就按新版本重新执行，并覆盖同一份反馈。反馈没写版本的，按 v1 算。
- 每一方只改自己的文件：设计方改 `assignments/`、`BOARD.md` 和设计代码，执行方只改 `feedback/`。这样两边同时推送也不会冲突。
- 推送前先 `git pull --rebase origin main`（只变基自己还没推送的提交）。提交信息前缀：设计方 `[design]`，执行方 `[exec]`。
- 例外：执行时碰到阻塞的小问题（路径、拼写、依赖版本），执行方可以做最小修正，单独提交并用 `[exec-fix]` 前缀，同时在反馈里列出。其他改动一律写成问题交回设计方。

## 任务单格式（设计方写）

```markdown
# Txxx 标题
- 版本：v1（每次修订加一，并写一句修订说明）
- 目标：一句话
- 依赖：前置任务或用户决定
- 输入：数据、权重、Run 编号（写路径，不写内容）
- 步骤：逐条可执行的命令
- 预期产物：文件或目录 + 位置（Mac / PVC / 仓库）
- 验收：哪些数字达到什么标准算通过
- 需要用户决定：没有就写“无”
- 反馈里必须报告：列出具体要回传的数字
```

## 反馈格式（执行方写）

```markdown
# Txxx 反馈
- 对应任务单版本：vN
- 状态：完成 / 部分完成 / 进行中 / 失败 / 阻塞
- 执行时间：开始—结束（北京时间）
- 实际执行的命令：与任务单不同的地方要标出来
- 结果：任务单“必须报告”里的每一项
- 产物位置：路径和 SHA256
- 偏差与问题：出现的报错、做过的 exec-fix、需要设计方决定的事
```

## 公开仓库规则（两方都要遵守）

- pilot 用的 Aster 数据集抽取完成后直接删除，不必再请用户确认（用户 2026-09-24 定）；正式放量用的数据集除外。
- 不提交凭证、token、kubeconfig 内容，也不提交新的内网地址或账号 ID。
- 不提交样本原文（生成文本、复核文本、`*.jsonl`）。反馈里只写统计数字、路径和 SHA。
- [round6/HANDOFF.md](../round6/HANDOFF.md) 第 1 节的硬规则继续有效：Aster 的并发、尝试次数和是否提交由用户决定；GPU 训练和推理只在 L20 上做；小规模 pilot 先行。

## 自动触发（双向）

| 方向 | 机制 | 延迟 |
|---|---|---|
| 设计方 → 执行方 | Mac 上常驻 `collab/watch_main.sh`：发现新的 `[design]` 提交就用 `collab/EXECUTOR_PROMPT.md` 启动一次执行方 agent；没有新设计时每 30 分钟也启动一次，跟进进行中的长作业 | 约 1 分钟 |
| 执行方 → 设计方 | 云端会话里后台运行 `collab/wait_for_feedback.sh`，发现非 `[design]` 提交就唤醒设计方；另有每小时一次的定时检查兜底（云端容器闲置被回收时，后台轮询会失效） | 约 1 分钟，最长 1 小时 |

在 Mac 上启动（仓库根目录，main 分支，工作区干净）：

```bash
EXECUTOR_CMD='claude -p' collab/watch_main.sh     # 用 Codex 就写 EXECUTOR_CMD='codex exec'
```

无人值守时执行方 agent 需要能直接运行命令，请在它自己的权限配置里放行 git、aster、kubectl 和 `.venv/bin/python`。日志在 `.git/collab_watch.log`。

暂停双方的自动动作：往 main 提交一个空文件 `collab/PAUSE`；删除它即恢复。

## Aster 平台限制（T016 实测，2026-09-24）

- 并发（`--concurrency`）最大 512。“并发拉满”就是 512，或者 Task 数少于 512 时取 Task 数。
- 一个 Run 最多 2,000 个 Task；一个数据集版本在同一个 Run 里只能出现一次，且最多选 2,000 个 Task。超过时拆成多个数据集、多个 Run。
- 设计方的打包脚本要按每份不超过 2,000 个 Task 输出（例如 `word_screen_v1/make_batch.py`），抽取脚本要支持一次读多个 Run。还没改的旧脚本，按 T016 的做法手动拆分，并在反馈里写明。
