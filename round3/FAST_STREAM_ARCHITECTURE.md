## 核心计算形状

```
用户/助手新 token
  → 共享词嵌入
  → [3 × Gated DeltaNet 状态更新 + 1 × 局部注意力] × 3
  → 用户/助手条件化风险头、类别头、证据充分头
  → 校准概率 → 版本化 allow/hold/block 控制器
```

目标 H2 是 12 层、宽度约 1024 的文本主干，9 个 Gated DeltaNet 层和 3 个局部 softmax 注意力层；完整消息与流式片段共享一套权重。Gated DeltaNet 层把历史压入**固定大小的递归状态**，局部注意力只留最近约 256 token 的 KV，另用消息边界与角色嵌入区分目标。每到一个 token 只更新状态并产生分类 logits；既不扫描全部对话，也不做词表输出投影或生成答案 token。状态大小随层/宽度和局部窗口决定，不随会话总长度增长。预计这会比当前 C1 的长上下文全 KV 更适合多会话吞吐；是否降低单 token P95 仍要在 L20 上实测。

此比例有实际预训练起点：官方 [Qwen3.5-0.8B-Base](https://huggingface.co/Qwen/Qwen3.5-0.8B-Base) 为 Apache-2.0 权重，24 层文本主干按 `3 × Gated DeltaNet + 1 × attention` 交替；官方[模型卡](https://huggingface.co/Qwen/Qwen3.5-0.8B)列出 24 层、隐藏宽 1024 与 6 个 attention 层。[Transformers 官方文档](https://huggingface.co/docs/transformers/main/model_doc/qwen3_5)说明 GDN 快速内核依赖 `causal_conv1d`/`fla`，缺失时会回退到较慢的 PyTorch 路径。我们先做 H1：保留官方完整文本主干，仅新增分类头和局部窗口实验；H1 验证语义与内核后，再按每组保留比例裁剪为 H2，并蒸馏恢复能力。视觉编码器与 LM 输出头不进入分类服务。

从官方配置估算，Qwen3.5 的 248,320 词嵌入 × 1024 宽度约 2.54 亿参数，不能误以为“只留 12 层”就一定小于现有 3.77 亿参数 C1。若 H2 的权重带宽成为主要瓶颈，再试第三步 H3：缩小分词表/宽度并做跨 tokenizer 蒸馏。H3 需要对中英、政治专名、繁简与对抗性拆词做独立回归；缩词表若破坏这些词，不接受速度收益。

按 BF16 粗算，9 个 16-head、128-dim 的 GDN 状态和 3 个局部窗口 256 的 GQA KV 会落在每会话数 MiB 级；具体状态张量、内核临时区和并发显存须由 H1/H2 代码计数，不能用这个估算宣称已节省显存。对照 C1 的完整 KV 随总前缀增长，H2 的优势应在长会话、多并发时最明显；短句单路可能被 kernel launch 与较大 embedding 吃掉。

## 训练与进入主线的条件

1. 在 L20 上对 H1 原版文本权重做分类头与前缀蒸馏，输入来自已分组去重的中英开放语料；教师用同一可见前缀的 Qwen3Guard-Stream 4B/0.6B 与 C1，损失包含风险/类别 KL、隐状态表征和不同 chunk 切法末态一致性。公开数据源标签只做实验分层，不伪装本项目政策金标。
2. 对 H2 裁剪每个 `3+1` 组时保留混合比例与层序，复用 H1 权重，再做同预算蒸馏。局部窗口从 256、512 做消融；窗口太短导致跨轮指代或后文危险反转漏判时，不用缓存收益掩盖能力回退。
3. 固定最终安全对齐集后，分别校准用户与助手头，再训练流式动作控制器。不得让整句教师看到未来 token 后给前缀伪标；独立人工风险起点仍是最终检测延迟标准。
4. 与通过质量门槛的 A0/C1 在**同一 L20、相同请求流和政策阈值**下比较：长上下文/并发 1、8、32 的首次/每次分类 P50/P95/P99、风险首次发现、每千安全输入 token 误拦、**ITPS（完成分类的新增输入 token/s）**、分类结果/s 与每会话状态显存。模型没有生成 token TPS。只有风险漏判/误拦不显著恶化，同时长会话 ITPS 或分类 P95 有稳定净收益，才替换基线。MoE、DSA 等只作为后续实测消融，不因名称新就加入。

这条路线的优势是可从已有混合架构预训练权重继承语义，而服务时仍是**真正的分类器**。最大风险是 GDN 有限状态遗忘远距离证据，以及 L20 上缺少适配内核造成理论复杂度优势无法兑现；两者都在验收中单独测。
