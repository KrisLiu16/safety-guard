## 结论与下一步

当前服务使用全局锁串行访问模型，并发增加没有带来相应吞吐提升，主要增加排队延迟。下一步先实现跨会话小批处理和缓存调度，并以同一 A0 权重、同一请求流验证分类一致性及 ITPS/延迟变化。完整输入和流式输入每次处理的 token 数不同，二者 ITPS 不能直接作为模型能力或优化倍数比较。

此前一次运行在高并发连接时发生 `ConnectionResetError`。扩大 HTTP listen backlog 后，32 客户端 mock 测试与本次 L20 重试均通过；这解决了该测试中的连接失败，不等于完成生产服务优化。
