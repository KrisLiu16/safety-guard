# 纯循环分类器：从零预训练候选 R24

数据接入进展：已实际下载 FineWeb2 中文和 FineWeb-Edu 英文各 10,000 篇原始样本，固定源版本并验证读取，见[语料接入记录](data/pretrain_sources/README.md)。语言预训练不等待最终安审标签；接下来处理清洗、去重、评测隔离、tokenizer 和打包。

2026-09-23。用户明确接受重新预训练，提出去掉全部稠密注意力。这里将其落实为**零 softmax token-to-token 注意力层**的候选；保留必要的跨 token 状态更新与逐 token FFN。当前只是结构、参数及训练预算方案，没有新模型训练在运行。现有 A0 仍是能力对照，混合方案 H24 保留作对照，不因理论复杂度就宣布被替代。

## 结构

首选可复现的纯 Gated DeltaNet（GDN）主干：24 层、宽度 1024，每层包含归一化、短因果卷积、GDN 状态更新、残差和 SwiGLU FFN。全部神经网络权重随机初始化；可以参考开源模块和维度，不加载 Qwen 的模型权重。GDN 属于线性注意力/循环网络，不是标准 softmax 注意力。若要求连线性注意力表述也完全不用，Mamba 系列是 SSM 对照，但名称不是验收条件。

概念计算为 `s_t = update(s_(t-1), x_t)`、`p_t = classifier(s_t, x_t, role)`。输入一段时用分块并行算法处理，流式输入用相同权重递归更新；每次追加至少返回块末尾的分类，单 token 追加返回该 token 位置的分类。状态属于每个会话，role/message 边界作为输入；无语言生成服务。

按已核查的 Qwen GDN 模块形状作预算参考，但不继承权重：新中英 tokenizer 暂拟 98,304 词，完整分类器约 **618,529,559** 参数。最后 6 层 FFN 改为每层 4 专家后约 **816,734,999** 参数，Top-1 与 Top-2 分开训练和测量。预算脚本见 [budget_r24.py](research/budget_r24.py)，原始形状记录见 [source metadata](research/qwen35_08b_source_metadata.json)。词表大小需先比较中文/英文压缩率、稀有实体、字节回退和分片边界，再冻结；不能先称已实现的精确模型规模。

首先测试普通 FFN 的纯 GDN，随后测试 MoE。FFN 仍可含稠密矩阵乘法；“零稠密注意力”不等于“零稠密计算”。MoE 只改变 FFN，避免专家切换导致历史递归状态不完整。路由训练与防塌缩问题继续遵循[混合/MoE 方案](HYBRID_MOE_ARCHITECTURE_V2.md)的要求。

## 复杂度及可能收益

固定宽度和状态维度时，主干每个新增 token 的历史更新成本不随历史 token 数 T 增长；整个输入序列的主干计算量对 T 近似线性。不存在逐 token 增长的注意力 KV。按 FP32 GDN 状态和 BF16 卷积状态粗算，每会话约 24 MiB + 1.125 MiB；不含回滚快照、内核工作区、激活和分配器，且短上下文未必比注意力 KV 小。

这支持长会话和多会话的成本目标，但不能推断短句延迟一定更低。投影、FFN、权重/状态读写、路由、kernel launch 和排队仍可能占主要时间。只保留 FFN 而不添加跨 token 模块会失去上下文交互，不是可行的“删除注意力”实现。

固定状态是有损历史表示。必须测长程指代、否定、引用/拒答、对话角色切换、风险后缀、延迟数千 token 后的实体关联与多次记忆更新。重新训练可能提升对任务信息的保留，不可能保证有限精度固定状态无损保存任意长历史。GDN 论文中的纯循环/混合对照也说明检索任务存在权衡。

分词与回滚仍是服务设计的一部分：稳定 token-ID 路径先验收；文本增量需要有界分词后缀和状态快照/重放，不能直接 crop 递归状态。最终比较必须包含这些开销。

## 从零预训练的数据与目标

从零学语言需要自然语料，现有开放安审样本和词表造句用于任务训练，不能代替语言预训练。候选自然语料从公开中英网页、百科和对话数据中按来源核实、清洗、去重后建立训练清单，保留文档边界并隔离评测族。FineWeb2 是多语言候选来源；现有下载及其许可核查不等于已备齐百亿 token。中英配比、tokenizer 与词族/来源隔离一起冻结。

语言阶段可以使用训练专用的 next-token loss：训练时对已知序列计算预测损失，无需生成采样循环；训练后从分类部署图移除词表投影，只保留风险/类别头。输入嵌入必须保留；若与训练输出头绑权，不能将其参数重复扣除。训练目标含 next-token prediction 与部署输出分类是两件事，不改变固定的分类服务接口。

训练顺序：

1. L20 内核与正确性探针：纯 GDN 分块/逐 token 状态一致性、完整反传有限值、长序列状态、有效训练输入 token/s、分类 ITPS、显存。主干从零权重不具备可解释风险能力，这一步只测数值和资源。
2. 约 100M token 管线 pilot：检查优化稳定性、held-out 中英 loss 和训练资源，不当作语言能力训练完成。
3. 扩到约 1B token 中间里程碑：检查学习曲线和冻结的小型分类/语义探针，决定 tokenizer/宽度/状态大小是否值得继续。要避免仅根据困惑度选择结构。
4. 10B–20B token 作为后续预算讨论的初始区间，根据学习曲线和实际任务能力调整。这是试验规划，不是 Chinchilla 定律保证的充分训练量；纯循环/MoE 的最优数据量也不能机械套稠密 Transformer 的比例。
5. 用公开安审训练标签、可靠教师的同一可见前缀分布和已质检合成数据进行分类训练；新 tokenizer 与教师按文本前缀对齐。最终安全政策校准等待对应标签，RL 仍只在分类可靠后研究流式动作收益。

训练时间用 `有效训练 token 总量 / L20 实测有效训练 token/s` 估算，加上验证、保存和故障开销。此前约 19 分钟的 LoRA 蒸馏不能外推为全参数预训练时间。100M、1B 和 10B–20B 均为方案里程碑，尚未提交执行，不将本次讨论表述为已经启动多日训练。

## 比较口径

部署仍只输出分类，主指标为 ITPS、首次/每次分类 P50/P95/P99、会话状态显存、固定误报率下召回和风险发现延迟。改变 tokenizer 后，原生 token/s 不可直接用于宣称跨模型加速：固定相同文本请求流，同时报告字节/字符每秒、请求/分类每秒、各自原生 ITPS 以及共同参考 tokenizer 的输入计数。

训练里程碑统计训练输入 token/s（包括前反向），不得与分类 ITPS 混用。短文本与 2K/8K 长对话、chunk 1/8/32、并发 1/8/32 分开报告。MoE 在数据/计算预算可比的条件下对照，不预设领域专家已经形成。
